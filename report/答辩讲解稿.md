## 一、架构设计（40 秒）

首先看系统的整体架构。（示意架构图）

系统按业务边界拆分为五个微服务：

- **book-service**（图书管理）：负责图书的增删改查和库存管理；
- **user-service**（用户管理）：负责用户注册登录、收货地址和 VIP 管理；
- **order-service**（订单管理）：负责订单的创建、查询和取消，同时通过 Feign 调用 book-service 扣减库存；
- **evaluation-service**（评价管理）：负责图书评价的提交和审核；
- **gateway-service**（统一网关）：作为系统的唯一入口，统一处理路由转发、鉴权过滤和跨域问题。

每个服务拥有独立的数据库，通过 API 通信，通过 Nacos 注册与发现。所有服务都集成了 Zipkin 链路追踪。

## 二、七大技术点实现（2 分钟）

### 1. Nacos 服务注册与配置中心

所有微服务都注册到 Nacos 注册中心。在 Nacos 控制台上可以看到 book-service 启动了 **2 个实例**，分别运行在 8081 和 8086 端口。同时还使用 Nacos 配置中心管理公共配置，支持动态刷新。

### 2. Ribbon 负载均衡

为了验证负载均衡，我部署了 book-service 的 **双实例**。通过网关多次请求 `/api/book/instance` 端点，可以看到响应的 port 字段在 8081 和 8086 之间**轮询切换**，证明 Ribbon 的负载均衡生效。

### 3. OpenFeign 服务调用

服务间通过 OpenFeign 实现声明式远程调用。以订单创建为例，order-service 通过 `BookFeignClient` 调用 book-service 查询图书信息和扣减库存。（展示代码）

```java
@FeignClient(name = "book-service")
public interface BookFeignClient {
    @PutMapping("/book/stock/{id}")
    Result<Void> updateStock(@PathVariable("id") Long id,
                             @RequestParam("quantity") Integer quantity);
}
```

同时 user-service 也通过 Feign 调用 order-service 查询用户订单，形成完整的服务间调用链路。

### 4. Sentinel 服务容错

Sentinel 方面，我在 order-service 和 evaluation-service 中通过**代码配置**定义了流控和熔断规则。

以 order-service 为例：createOrder 接口限流 10 QPS，listOrders 限流 20 QPS，cancelOrder 限流 5 QPS。同时配置了慢调用熔断：当请求响应时间超过 2000 毫秒且比例达到 50% 时，触发熔断 10 秒。

所有受保护的方法都添加了 `@SentinelResource` 注解，并提供了 fallback 和 blockHandler 方法，在限流或熔断时返回友好的提示信息。（展示限流测试结果）

### 5. Gateway 网关

网关运行在 8080 端口，配置了四个路由规则，将 `/api/book/**`、`/api/user/**`、`/api/order/**`、`/api/evaluation/**` 分别转发到对应的微服务。

同时实现了全局鉴权过滤器：白名单路径（如登录、图书列表）直接放行，其他路径检查 Authorization 请求头，未认证的请求返回 401。还配置了 CORS 跨域支持和 Sentinel 网关限流。

### 6. Spring Cloud Stream 消息驱动

在消息驱动方面，order-service 通过 StreamBridge 向 RabbitMQ 发送订单事件消息，evaluation-service 通过 Consumer 函数接收消息。（展示代码）

```java
@Component
public class OrderEventPublisher {
    public void sendOrderEvent(Order order) {
        Message<Order> message = MessageBuilder.withPayload(order)
            .setHeader("routingKey", "evaluation.order").build();
        streamBridge.send("orderEventOutput", message);
    }
}
```

这部分因为当前环境没有安装 RabbitMQ，所以代码已就绪但实际运行尚未验证。

### 7. 分布式链路追踪

最后是链路追踪。系统集成了 Micrometer Tracing 和 Zipkin，配置了 100% 采样率。在 Zipkin UI 中可以查看完整的服务调用链路，包括各节点的耗时和调用关系拓扑。

## 附录：答辩提示

### 可能被问到的问题

1. **Q: 为什么用代码配置 Sentinel 规则而不是在控制台配？**
   - A: 代码配置可以随项目版本管理，保证规则的一致性，适合开发环境。生产环境可以结合控制台动态调整。

2. **Q: 负载均衡用的是 Ribbon 还是 LoadBalancer？**
   - A: Spring Cloud 2023 默认使用 Spring Cloud LoadBalancer，但概念上和 Ribbon 一致，都实现了客户端负载均衡。

3. **Q: 订单服务调用图书服务扣减库存，如果失败怎么办？**
   - A: 当前通过 Sentinel 降级处理，返回错误提示。更好的方案是引入 Seata 分布式事务或使用 TCC 模式。

4. **Q: 网关鉴权的 token 怎么生成和验证？**
   - A: 当前是简化版本，只校验 Authorization 头是否存在。完整方案需要集成 JWT，在登录时签发 token，在网关中验证签名。

5. **Q: 部署了几个 MySQL 实例？**
   - A: 每个微服务独立数据库，但共用一个 MySQL 实例的不同 database。生产环境建议独立部署。
